Putting the site online

Nexora Homes, on Hostinger, with the domain from GoDaddy.

Read this through once before you start

The whole job is about twenty minutes of clicking, plus waiting for the domain to catch up, which is out of anyone’s hands.

00The question you asked: is there a build step?

No. There is nothing to compile, generate, or run.

The files in this folder are the finished website. index.html is already the final file a browser reads: the styling and the code are written inside it, so there is no separate CSS or JS file to assemble, no npm, no framework, no Node, and no Python needed to produce it.

Upload the folder and the site is live. That is the whole build process.

The one Python file, and what it is not

set-domain.py in this folder is a convenience, not a build step. It writes your domain into four files so link previews and Google get the full address. You can do the same by hand in a text editor in two minutes — step 02 covers both ways.

If you ever saw build-preview.py in the project, that only squeezed the site into a single file for the preview links. It has nothing to do with your website and is not in this folder.

02Put your domain into the files

Four files carry a placeholder, SITE_URL_HERE, because the site was built before the domain was known. These are the addresses WhatsApp, Facebook and Google read. The site works without this step, but link previews and search results will not.

The easy way, if you have Python

Open a terminal in this _deploy-docs folder and run:

python3 set-domain.py yourdomain.com

Use your real domain. If you want the site at www.yourdomain.com, type it with the www. and the script sets that up too. It prints what it changed, and it is safe to run twice.

The other way, no Python needed

Open these files in any text editor and replace every SITE_URL_HERE with your address, written in full and with no slash on the end: https://yourdomain.com

FileHow many
index.html3 places
about.html3 places
sitemap.xml2 places
robots.txt1 place

Then open .htaccess, find the block headed Pick ONE address for the site, and remove the #  from the front of the lines under whichever you want, www or non-www.

Uncomment one, never both

Turning on both the www and the non-www rule sends visitors round in a loop and the site stops loading entirely.

03Upload to Hostinger

Log in to Hostinger and open hPanel. Go to your website, then File Manager. You want the folder called public_html. That is the web root: whatever sits there is what the world sees.

If a default Hostinger placeholder page is in there already, delete it first, or your site will not show.

The fast way

  1. Zip up the contents of this folder. Not the folder itself — the files inside it: index.html, about.html, assets, and the rest.
  2. In File Manager, open public_html and upload that zip.
  3. Right-click it and choose Extract.
  4. Delete the zip afterwards.

When it is done, index.html must sit directly inside public_html. If you instead see public_html/nexora/index.html, everything is one level too deep and the site will not load. Move the files up a level and remove the empty folder.

Or by FTP

hPanel shows your FTP host, username and port under Files → FTP Accounts. Connect with FileZilla, go to public_html, and drag everything in.

The .htaccess file is hidden. Do not lose it.

That name starts with a dot, which makes it hidden. File Manager and FileZilla both hide it by default, so it is very easy to upload everything else and silently leave it behind.

In Hostinger File Manager, turn on Show hidden files in the settings menu. In FileZilla: Server → Force showing hidden files.

Then confirm .htaccess really is in public_html. Without it you lose the https redirect, the compression, the caching and the custom 404 page. The site still loads, so nothing looks obviously wrong, which is exactly why it is worth checking.

04Point the GoDaddy domain at Hostinger

The domain is at GoDaddy and the site is at Hostinger, so GoDaddy has to be told where to send people. Two ways — pick one.

Option A — nameservers (recommended)

Hostinger then handles all DNS for the domain, which makes everything afterwards easier, including email.

  1. In Hostinger hPanel, find the nameservers for your plan. They appear in your hosting plan’s details, usually under a heading like Nameservers, or in the domain setup screen. There are normally two, sometimes four. Copy them exactly.
  2. Log in to GoDaddy, go to My Products, find the domain, and open its DNS or Nameservers settings.
  3. Choose to use your own / custom nameservers and enter the ones you copied. Save.
  4. Back in hPanel, add the domain to your hosting plan if it is not already there, so Hostinger knows to answer for it.
Read the nameservers off your own hPanel

Do not use nameserver addresses from a blog post, from a video, or from memory. They differ between plans and they do change. Yours are the only correct ones.

Option B — an A record

Use this if you want GoDaddy to stay in charge of DNS, for instance because email is set up there.

  1. In hPanel, find your hosting account’s IP address, shown in the plan details.
  2. In GoDaddy, open the domain’s DNS records and set:
TypeNameValueTTL
A@your Hostinger IP1 hour
CNAMEwww@1 hour

If an A record for @ already exists, edit it rather than adding a second. Two A records for @ pointing at different places make the site load about half the time, which is a horrible thing to debug.

Then add the domain to your hosting plan in hPanel.

Then wait

DNS changes are not instant. Usually minutes to an hour, but it can take 24 to 48 hours to reach everyone. During that window some people see the new site and some do not. That is normal, not a fault. Check progress at dnschecker.org.

05Turn on https

Once the domain actually points at Hostinger, go to hPanel → Security → SSL and install the free certificate. On most plans this happens by itself within an hour of the domain resolving.

Do this after the domain is pointing, not before

The certificate cannot be issued until the domain reaches Hostinger.

.htaccess already forces every visitor onto https, which means that until the certificate exists, visitors get a browser security warning. So: point the domain, install the certificate, then check the site.

If you must test before the certificate is in, open .htaccess and put a # at the start of the four lines of the Send everyone to https rule. Take the # back off once the certificate is installed.

06Check it

  • https://yourdomain.com loads the home page
  • The padlock shows in the address bar
  • http://yourdomain.com (no s) jumps to https by itself
  • Scrolling the top of the home page plays the film
  • The About link in the menu works
  • The WhatsApp buttons open a chat to 0323 450 8739
  • All eight products show their photo
  • yourdomain.com/not-a-real-page shows the Nexora 404 page, not a bare Hostinger error
  • On your phone the top is a still photo, not the film. That is deliberate: phones get a sharp still instead of a 6 MB download.

If the film does not play on a laptop, check in File Manager that assets/hero-scrub.mp4 really uploaded and is 6,320,529 bytes. A half-finished upload is the usual cause.

07Changing things later

Edit the file, upload it over the old one. That is all.

WhatHow
Text, prices, wording Edit index.html or about.html and re-upload. Live immediately — .htaccess tells browsers never to cache the pages.
A product photo Put the new picture in assets/, keeping the same file name, or use a new name and change it inside index.html too.
Phone number It appears several times. Search index.html, about.html and 404.html for 923234508739.
About replacing a photo under the same name

Photos are cached in visitors’ browsers for a week. If you replace one and keep the name, people who already visited may see the old one for a few days. Giving the new file a new name avoids this completely.

Always keep a copy of the folder on your own computer. The server copy is the only other one.

What you seeWhat it is

500 Internal Server Error, everything dead Almost always .htaccess. Rename it to htaccess-off and reload. If the site comes back, something in it is not supported by your plan — tell me and I will trim it.
Page loads, no styling, no photos The assets folder did not upload, or it landed next to public_html instead of inside it.
“Too many redirects” Both the www and non-www rules in .htaccess are on. Only one may be. Comment the other out with a #.
