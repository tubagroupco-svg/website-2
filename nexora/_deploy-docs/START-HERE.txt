================================================================
  NEXORA HOMES, WEBSITE
  How to put it online on Hostinger and point your GoDaddy
  domain at it.
================================================================

Read this once through before you start. The whole job is about
twenty minutes of clicking, plus waiting for the domain to catch
up, which is out of anyone's hands.


----------------------------------------------------------------
  FIRST, THE QUESTION YOU ASKED: IS THERE A BUILD STEP?
----------------------------------------------------------------

No. There is nothing to compile, generate, or run.

The files in this folder ARE the finished website. index.html is
already the final file a browser reads: the styling and the code
are written inside it, so there is no separate CSS or JS file to
assemble, no npm, no framework, no Node, no Python needed to
produce it.

Upload the folder and the site is live. That is the whole build
process.

There is no script of any kind in this folder. Nothing to run,
nothing to install. Every file here is either a web page, a
picture, a font, or a plain settings file the server reads.

----------------------------------------------------------------
  STEP 1. YOUR DOMAIN IS ALREADY IN THE FILES
----------------------------------------------------------------

Nothing to do here. nexorahomes.co is already written into every
page, sitemap.xml and robots.txt, and .htaccess is set so
www.nexorahomes.co sends visitors to nexorahomes.co.

Skip to step 2.

  ONLY IF YOU CHANGE DOMAIN LATER:

    Open these files in any text editor and replace every
    https://nexorahomes.co with the new address, written in full
    and with NO slash on the end:

        index.html            (3 places)
        about.html            (3 places)
        panel-4in.html        (3 places)
        panel-wide.html       (3 places)
        switches-soft.html    (3 places)
        switch-8gang.html     (3 places)
        switch-display.html   (3 places)
        lock.html             (3 places)
        curtain-motor.html    (3 places)
        dimmer.html           (3 places)
        sitemap.xml           (10 places)
        robots.txt            (1 place)

    Every page follows the same pattern, so it is quicker with a
    find-and-replace across the whole folder than file by file, if
    your text editor can do that.

    Then open .htaccess, find the block headed "One address for
    the site", and make sure exactly ONE of the two redirect
    blocks is uncommented. Never both: the two rules would send
    visitors round in a loop and the site would stop loading.

----------------------------------------------------------------
  STEP 2. UPLOAD TO HOSTINGER
----------------------------------------------------------------

Log in to Hostinger and open hPanel. Go to your website, then
File Manager. You want the folder called public_html. That is
the web root: whatever sits there is what the world sees.

  If there is a default Hostinger placeholder page in there
  already, delete it first, or your site will not show.

  THE FAST WAY:

    1. Zip up the CONTENTS of this folder. Not the folder
       itself, the files inside it: index.html, about.html,
       assets, and the rest.
    2. In File Manager, open public_html and upload that zip.
    3. Right-click it and choose Extract.
    4. Delete the zip afterwards.

    When it is done, index.html must be sitting directly inside
    public_html. If instead you see public_html/nexora/index.html
    then everything is one level too deep, and the site will not
    load. Move the files up a level and remove the empty folder.

  OR BY FTP:

    hPanel shows your FTP host, username and port under Files,
    FTP Accounts. Connect with FileZilla, go to public_html, and
    drag everything in.

  ABOUT .htaccess, PLEASE READ:

    That file starts with a dot, which makes it hidden. File
    Manager and FileZilla both hide it by default, so it is very
    easy to upload everything else and silently leave it behind.

    In Hostinger File Manager, turn on "Show hidden files" in
    the settings menu.
    In FileZilla, Server menu, "Force showing hidden files".

    Then check that .htaccess really is in public_html. Without
    it you lose the https redirect, the compression, the caching
    and the custom 404 page. The site still loads, so nothing
    will look obviously wrong, which is exactly why it is worth
    checking.


----------------------------------------------------------------
  STEP 3. POINT THE GODADDY DOMAIN AT HOSTINGER
----------------------------------------------------------------

The domain is at GoDaddy and the site is at Hostinger, so
GoDaddy has to be told where to send people. Two ways. Pick one.

  OPTION A, NAMESERVERS. Recommended.

  Hostinger then handles all DNS for the domain, which makes
  everything after this easier, including email.

    1. In Hostinger hPanel, find the nameservers for your plan.
       They are shown under your hosting plan's details, usually
       in a panel headed Nameservers or in the domain setup
       screen. There are normally two, sometimes four. Copy them
       down exactly as shown. Do not use nameservers from a blog
       post or from memory, including any in this guide: read
       them off your own hPanel, because they differ between
       plans and they do change.

    2. Log in to GoDaddy. Go to My Products, find the domain,
       and open its DNS or Nameservers settings.

    3. Choose to use your own / custom nameservers, and enter
       the ones you copied. Save.

    4. In hPanel, add the domain to your hosting plan if it is
       not already there, so Hostinger knows to answer for it.

  OPTION B, AN A RECORD. Use this if you want to keep GoDaddy
  in charge of DNS, for instance because email is set up there.

    1. In hPanel, find your hosting account's IP address. It is
       shown in the plan details.

    2. In GoDaddy, open the domain's DNS records and set:

         Type   Name    Value                TTL
         A      @       your Hostinger IP    1 hour
         CNAME  www     @                    1 hour

       If an A record for @ already exists, edit it rather than
       adding a second one. Two A records for @ pointing at
       different places will make the site load about half the
       time, which is a horrible thing to debug.

    3. In hPanel, add the domain to your hosting plan.

  THEN WAIT.

  DNS changes are not instant. Usually it is minutes to an hour,
  but it can take up to 24 to 48 hours to reach everyone. During
  that window some people see the new site and some do not, and
  that is normal, not a fault. Check progress at
  https://dnschecker.org by entering your domain.


----------------------------------------------------------------
  STEP 4. TURN ON HTTPS
----------------------------------------------------------------

Once the domain actually points at Hostinger, go to hPanel,
Security, SSL, and install the free certificate for the domain.
On most plans this happens by itself within an hour of the
domain resolving.

Do this AFTER the domain is pointing, not before. The
certificate cannot be issued until the domain reaches Hostinger.

The .htaccess already forces every visitor onto https. Which
means that until the certificate is installed, visitors get a
browser security warning. So: point the domain, install the
certificate, then check the site. If you must test before the
certificate exists, open .htaccess and put a # at the start of
the four lines of the "Send everyone to https" rule, and take
the # off once the certificate is in.

  [ ] scrolling the top of the home page plays the film
  [ ] the About link in the menu works
  [ ] the WhatsApp buttons open a chat to 0323 450 8739
  [ ] the eight products all show their photo
  [ ] clicking a product opens its own page, with a working
      link back to the range and to two or three other products
  [ ] the About page shows a photo for each of the five places
      the range gets fitted, not just text
  [ ] nexorahomes.co/a-page-that-does-not-exist shows the
      Nexora 404 page, not a bare Hostinger error

  that assets/hero-scrub.mp4 really uploaded, and that it is
  6,320,529 bytes. A half-finished upload is the usual cause.


----------------------------------------------------------------
  CHANGING THINGS LATER
----------------------------------------------------------------

Edit the file, upload it over the old one. That is all.

  Text, prices, wording      edit whichever page and re-upload.
                             Live immediately, because .htaccess
                             tells browsers never to cache the
                             pages.

  A product's own page       each product's page is a separate
                             file, named after it: panel-4in.html,
                             panel-wide.html, switches-soft.html,
                             switch-8gang.html, switch-display.html,
                             lock.html, curtain-motor.html,
                             dimmer.html. Edit that file the same
                             way as any other page.

  A product photo            put the new picture in assets/ and
                             either keep the same file name, or
                             use a new name and change the name
                             everywhere it is used: the card on
                             index.html and that product's own
                             page both reference it.

                             NOTE: photos are cached in visitors'
                             browsers for a week. If you replace
                             one and keep the name, people who
                             already visited may see the old one
                             for a few days. Giving the new file
                             a new name avoids this completely.

  Phone number               it appears several times across every
                             page. Search each file for
                             923234508739 and change each.

Always keep a copy of the folder on your own computer. The
server copy is the only other one.

----------------------------------------------------------------
  IF SOMETHING IS WRONG
----------------------------------------------------------------

  Site shows a Hostinger placeholder
      The old default page is still in public_html. Delete it.

  "Index of /" or a list of file names
      index.html is not in public_html, or it is one folder too
      deep. Move it up.

  500 Internal Server Error, everything dead
      Almost always .htaccess. Rename it to htaccess-off and
      reload. If the site comes back, something in that file is
      not supported by your plan. Tell me and I will trim it.

  Page loads, but no styling, no photos, plain black text
      The assets folder did not upload, or it landed next to
      public_html instead of inside it.

  Redirect loop, "too many redirects"
      Both the www and the non-www rule in .htaccess are
      switched on. Only one may be. Comment the other back out
      with a # at the front of its lines.

  Film does not play, everything else fine
      There are two cuts. Check both uploaded completely:
        assets/hero-scrub.mp4           6,320,529 bytes (laptops)
        assets/hero-scrub-portrait.mp4  2,029,846 bytes (phones)

  Old version keeps showing after an edit
      Hard refresh: Ctrl+Shift+R, or Cmd+Shift+R on a Mac.
